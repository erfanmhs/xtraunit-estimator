# Feedback round — 2026-09-08

Erfan's feedback after extended real use, mostly on **iPhone**. Every item is
numbered so nothing gets lost and each can be ticked off independently.

**Standing rule for this round:** the phone is the design target. The desktop
must stay correct and functional, and gets checked on every item — but where
the two conflict, the phone wins.

Status key: `[ ]` not started · `[~]` in progress · `[x]` done · `[>]` deferred
with a reason.

---

## A. Projects list (opening screen)

- [ ] **A1** Swipe left on a project row → actions, same as the rest of the app.
      At minimum Delete; plus Archive ("minimize") and Edit.
- [ ] **A2** Long-press a project → iOS-style jiggle/edit mode for reordering.
      Drag to reorder, one tap anywhere exits edit mode.
- [ ] **A3** Reorder has to persist (needs a `sort_order` column on `projects`).

## B. Inside a project

- [ ] **B1** The three-dot menu only offers Delete. Needs: Edit project info,
      Duplicate, Archive, Delete.
- [ ] **B2** The Plans section must collapse to the same size as the Scope,
      Pricing, Estimate and Proposal sections. Right now it dominates the page.

## C. Scope of work — major overhaul

- [ ] **C1** **Structure / WBS.** How many line items, what breakdown, what
      professionals actually do, what format reads best, and what will support a
      scheduling feature later. → see `docs/SCOPE-WBS-DESIGN.md`.
- [ ] **C2** Trade picker needs an **"Other trades"** free-text option; the AI
      reads what's typed and maps it to the right CSI division.
- [ ] **C3** "Full building" vs "Trades" must read as a **major category
      choice**, visually distinct from ordinary buttons, so it's obvious a
      sub-choice follows.
- [ ] **C4** The expand triangle is too small to read as "this opens". Bigger,
      or a different icon.
- [ ] **C5** **Generate / Regenerate button.** This is the headline action.
      Distinct shape, brand accent, not oversized. Dynamic states:
      - nothing selected → off/disabled
      - trades selected, nothing generated → "Generate Scope of Work"
      - generated, no changes since → hidden (or quiet)
      - inputs changed since last run → reappears as "Regenerate"
- [ ] **C6** "Add line" → **"Add Item"** (scope and pricing both).

## D. Pricing

- [ ] **D1** Put a **`$`** in front of every amount field so it's obvious a
      price is wanted.
- [ ] **D2** The **Exclude** button is far too easy to hit by accident. Move it,
      and add a yes/no confirm.
- [ ] **D3** Excluding must **not** wipe the numbers. Keep the quantity and
      price; move the line into an **Exclusions** section at the bottom.
- [ ] **D4** Option to carry exclusions through to the proposal under an
      "Exclusions" heading.
- [ ] **D5** Delete is available **from** the Exclusions section, for lines the
      user really does want gone.
- [ ] **D6** "Add sub quote" / "Add subcontractor quote" → **"Apply Additional
      Quote"**.

## E. Waiting / progress (global)

- [ ] **E1** Every generation *and* every move between stages (Plans → Scope →
      Pricing → Estimate → Proposal) shows a clear indicator of what is
      happening.
- [ ] **E2** While it runs, the control is locked so it can't be fired twice.

## F. Proposal

- [ ] **F1** Visible separation between the live preview and the editor.
- [ ] **F2** Signing order: name and email first → then the checkbox becomes
      available → then sign.

## G. PDF viewer / takeoff

- [ ] **G1** The sheet-categorization panel should behave like the layer panel:
      dismiss on an outside tap, and not swallow the whole screen.
- [x] **G2** **Bug** — the area tool doesn't draw the area label in the middle
      of the shape. *Only one label per layer was drawn, anchored on the biggest
      run and offset to the side. Each area now carries its own value in the
      middle, centred on the true area centroid.*
- [x] **G3** **High priority** — the precision point must sit at the **centre of
      the crosshair**, not at the finger contact point. *Aim point lifted 34 px
      above the contact patch; loupe, rubber band and placed point all use it;
      target ring drawn on the sheet.* **The 34 px needs tuning on a real
      thumb — see the note below.**
- [x] **G4** Two fingers = pan and zoom, and nothing else. No point, no line, no
      preview, no marks of any kind. *A second finger now abandons and restores
      any drag, and no tool can start an edit while two fingers are down.*

## H. Design system

- [x] **H1** Move off the XtraUnit brand palette for the whole UI. Neutral,
      modern greys/blacks/whites that hold up over long screen sessions and suit
      the glass look. *Cool slate, approved from the sample page.*
- [x] **H2** One brand colour per company (red for XtraUnit) used **as an accent
      only** — Generate with AI, project headline, key actions. *The garnet
      backdrop wash and the red-washed stage cards are gone; change `--accent`
      to rebrand.*
- [x] **H3** Build the palette as tokens so light/dark is a switch, and add the
      setting later. *Done now rather than later — the switch is in Settings,
      dark stays the default, no flash on load.*
- [x] **H4** Raise contrast between sections on a page; the glass currently
      blurs the boundaries. *Surfaces now sit lighter than the page instead of
      darker, so they lift; the glass look is kept.*

## I. Layout, flow and naming

- [ ] **I1** Buttons follow the order the eye and hand actually move. Worked
      example: on plan upload, **Save** sits at the top, so the user scrolls
      down to pick sheets and back up to save. It belongs at the bottom, after
      the selection.
- [ ] **I2** "Apply changes to the scope" moves to the **bottom** of the
      gaps/assumptions/questions page, after the user has answered everything.
- [ ] **I3** **Naming review across the whole app.** Short, plain, unambiguous.
      Flag anything odd. Known: "Clear" → "Remove Selected".
- [ ] **I4** Use iOS and other well-known apps as the placement reference.

## Note on verifying G3 on a device

`AIM_LIFT` in `PlanViewer.tsx` is **34 px**, chosen as roughly half a fingertip
contact patch plus clearance. It is a starting value, not a measured one — the
browser pane has no fingers, so this cannot be validated anywhere except on
Erfan's actual phone with his actual thumb.

If points land **above** where he means, lower it. If his finger still covers
the target, raise it. It's one constant with a comment on it.
